# 3dtrees changes to raycloudtools

What our `develop` adds over upstream (`git log main..develop`), as it stands: rewritten as `develop` changes, not a running history, until we version. `main` mirrors upstream. All flags are on `rayextract trees`. With every flag at its default the fits are upstream's; the one difference in output is the `<cloud>_taper.txt` sidecar every run now writes.

- `--export_sections` writes what `rayextract trees` measures and decides but throws away, beside `_trees.txt`: `_sections.txt`, one row per `_trees.txt` segment in the same order (the measured radius `rad` with its accuracy and point count, the centroid before and the centre after the centre step, direction, reach, `radius_scale`, and the split test at the section's top: gap, span, end points, cluster sizes); `_sections.bin`, the `section_id` owning each ray (int32 in cloud order, like `_labels.bin`); and `_modules.txt`, per tip, the points the ownership assigns past its end points (count, mean, covariance, top, reach). A joint wood/leaf fit needs them: ownership to start from, RCT's own radius as data, each split's margin, and the distal crown as terminal modules (the ~29 % of a tree's points more than 30 cm outside every cylinder; 3dtrees research 88). Output-neutral: off by default, and with it set `_trees.txt`, `_labels.bin` and `_taper.txt` are byte-identical; the graph code is untouched, so graph caches stay valid.
- `getRootsAndSegment` pads its height-field grid by 0.1 mm, so the cloud's highest-x/y point can't index one cell past the end and corrupt the heap (csiro-robotics/raycloudtools#48, `malloc(): invalid size`). A crash fix: the seeds, graph and output are unchanged (byte-identical on savanna0 tile 1_0), but it edits `raysegment.cpp`, so graph caches keyed on that code are rebuilt once.
- `--geometric_centre` and `--slab_sections` **change fits when set** (off by default). RCT centres each section with one algebraic circle step on the points it reaches through the shortest-path graph, which after a split are a thin strip down one side of the branch, so axes sit off-centre on thin wood. The first iterates a robust geometric circle fit with the taper radius as a prior (trunk girth bands stay on the algebraic step); the second fits each section made by a split on its share of the whole slab of points. Together they halve the breast-height axis offset on the bench and are the only axis gain on wood below the refit's 1 cm gate; radii barely move (3dtrees research 54).
- `--trunk_gap`, `--trunk_span_ratio` and `--trunk_splits` **change fits when set.** They give the trunk split its own thresholds and rounds. Multi-stem plants (mulga clumps) are fused into one root group, but loosening the shared gap/span rules to split them also splits branches; separate trunk settings split stems and leave branching alone.
- `--taper_prior_sd`, `--taper_exponent` and `--stem_taper` **change fits when set.** One taper per plot fits neither saplings nor big trees. These flags blend each tree's own taper with the prior by how much evidence the tree has, let the prior vary with height, and taper radii along each stem rather than keeping them constant between forks. Every run now also writes `<cloud>_taper.txt`, one line of taper diagnostics per tree, so the prior can be checked.
- `--taper_weight W` **changes fits.** It fixes the weight of the taper prior that every radius is shrunk towards. Upstream weights it by a running sum over all trees fitted so far, so each tree's radii depend on the rest of the cloud and on processing order: crop a tile or change one flag, and almost every tree moves. With a fixed weight, each tree depends only on its own points, so fits are stable across tiles and verdicts carry over.
- `--graph_cache FILE` saves the shortest-path graph and loads it on rerun. The graph is about 75 % of the run time and depends only on the cloud and a few flags, so tuning later flags or patching the fitting reruns about 4× faster with the same output.
- `--labels_only` writes one tree id per ray (`_labels.bin`) instead of `_segmented.ply`, and `--no_mesh` skips `_trees_mesh.ply`. Those two files rewrite or re-derive data we already have, at about 1.7 GB and 1.2 GB per plot.
- `connectPointsShortestPath` no longer keeps the full kNN distance matrix. That matrix was 5.5 GB of a 15.7 GB peak, which limited how many tiles could run at once. Output is unchanged.
